Adding a source

A source is one connector reading one system into the graph. Sources come inside context packs, so adding a source means adding a pack.

Add a shipped pack

  1. Find the pack in the library. Its page lists the questions it asks and the credential names it reads.
  2. Add it to the running instance:

bash archi add git-code --answer git_code_repo_url=https://github.com/example/repo.git

--answer ID=VALUE answers one of the pack's questions. The id is the pack name, with dashes as underscores, then an underscore and the question id. archi add edits the registry, claims ownership of the new source, commits the instance repository, and publishes again. 3. Run archi doctor. The source-freshness check shows the new source's age against its limit.

To choose packs at the start, use archi init --with <pack>.

Credentials

A pack names its credential variables (its page lists them). It never holds a value. Packs that need no credential, such as docsite, publish with nothing configured.

Where the value goes. Put it in the instance's .env, one KEY=value per line, or in a cookie file whose path an init question asks for. .env is mode 0600 and git ignores it. Quotes around a value and a leading export are allowed.

What reads it. archi add, archi ingest and every other okg command archi runs add every value in .env to the environment of the steps that ingest. A value exported in the shell wins. A value added to .env takes effect at the next archi ingest or archi add. Keys that change how programs run (PATH, LD_*, PYTHON*, GIT_*, SSH_*, OKG_*) are not passed on; archi names them on stderr.

What does not read it.

  • okg run by hand. To refresh sources, run archi ingest instead (--include <source id>,... for some of them, --publish to publish after).
  • The first ingest of archi init, because archi init writes .env itself. For a pack selected at archi init, export the value in the shell, then add it to .env.
  • The ops runtime worker, which you start yourself. Start it from a shell that has the credentials exported.

Connectors that read a cache

Some connectors read a cache that another tool writes, for example the CRIC topology or the DBS dataset catalog. Each cache has a contract: where it lives and what it holds. See connector caches. A pack's prepare: step can write a cache before the first run, so a bare install has its input.

A source Archi does not ship

Write a pack. A pack can live in another pip package and register through the archi.packs entry point. See Contributing a pack.
