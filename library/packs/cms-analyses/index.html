Pack: cms-analyses

CMS physics group and technique hubs, and rules joining analysis ids across CDS records, TWiki pages and analysis notes (code is not linked).

Field Value
Kind context
Version 0.1.0
Needs a credential to publish yes
Okg modules it needs document_starter, person, extraction
Packs it needs twiki, cds, analysis-notes

In which bundles

  • Default in: cms-physics
  • Optional in: none

Add it to an instance with archi add cms-analyses.

Sources

  • cms-analyses.physics_entities
  • cms-analyses.physics_vocabulary

Questions

This pack asks no questions.

Credentials

The manifest names no credential variable.

Freshness limits

archi doctor compares each source's age with its limit.

Source Longest acceptable age
cms-analyses.physics_entities 7d
cms-analyses.physics_vocabulary 7d

Invariants

The pack owns these checks. They leave with it.

Name Severity What it checks
cms_analyses_coverage error The physics vocabulary and entity sources must have live hubs and entities. Required live subtypes: physics_analysis_group, physics_object_group, physics_technique, physics_concept, physics_topic. Both sources declare their nodes in code, so a missing one means the source did not run or was dropped from the install.
cms_analyses_enricher_edges warn None of the cross-link rules' derived edges exists: no CDS record to analysis note, and no PAG to POG. The PhysicsCrossLinker enricher is probably not wired in the deployment's enrichers block (the cms-analyses README has the block to paste).
